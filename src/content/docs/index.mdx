## Delivery for Terraform, Pulumi and SQL teams.

Approvals and audit as jobs on GitHub, GitLab or Forgejo. No platform to buy.

## Your delivery

Every team delivers in its own way. Most teams do these steps.

- Build and test a change
- Plan it
- Get an approval
- Release it
- Watch it in production

chant does each step as a job in GitHub, GitLab or Forgejo. You keep the steps you have and add the ones you need.

## Pick your tool

- [terragucci](https://intentius.io/terragucci/) for Terraform teams
- [plywood](https://intentius.io/plywood/) for Pulumi teams
- [SQL Yodeler](https://intentius.io/sql-yodeler/) for SQL teams

All three are built on [chant](https://intentius.io/chant/). See how they [compare](/compare/terraform-platforms/) with HCP Terraform, Pulumi Cloud and Spacelift.

## A way out of Terraform

chant writes each cloud's own format, such as CloudFormation or Kubernetes YAML. Each chant type matches one resource in that format, field for field, like the L1 classes in AWS CDK. The cloud runs the output without Terraform. There is no state file.

The output is plain CloudFormation or YAML. If you stop using chant, you keep it.

You can move one resource at a time. Nothing is deleted or created again.
